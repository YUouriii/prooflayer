How it works

The verification engine is separate from the agent itself. That separation is the whole point: the thing being checked can never grade its own homework.

01
Agent makes a claim
"I sent invoice #4821 to john@example.com."
02
Provider fetches evidence
Gmail, and later Slack, GitHub, Stripe… are queried independently.
03
Engine evaluates
Deterministic rules turn evidence into a verdict. No vibes.
04
Structured result
Status, confidence, reason, evidence table, audit trail.

Trust is engineered, not promised

  
    
    
  • Organization isolationEvery record is scoped server-side. Cross-org reads return 404.
    • 
    
  • API-key authArgon2id-hashed keys with granular scopes and instant revocation.
    • 
    
  • Encrypted credentialsOAuth tokens encrypted at rest (AES-256-GCM). Never logged.
    • 
    
  • Audit trailEvery verification, login and key change recorded — without secrets.
    • 
    
  • Rate limitingGlobal and per-endpoint budgets; 429s follow the error contract.
    • 
    
  • Request IDsEvery response carries X-Request-Id for correlation.
    • 
    
  • Independent evidenceInfrastructure failures yield INCONCLUSIVE — never a false FAILED.
    • 
    
  • IdempotencySafe retries: same key returns the original record, conflicts get 409.
    •
